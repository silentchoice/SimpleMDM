# 关系化通用 MDM 实施选择与决策记录

日期：2026-07-31

本文记录在既定规格下采用的默认实现选择。Task 12 完成发布与最终验收后补充最终验证结果。

| 范围 | 默认选择 | 理由与影响 | 当前验证 |
|---|---|---|---|
| 数据库基线 | 使用单一 Flyway V1 从空库建表，不迁移旧数据 | 避免旧 JSON 与部门名称关系污染新模型 | 空库迁移与外键测试通过 |
| 部门关系 | 使用非空 `department_id` 与同系统外键 | 部门改名不破坏引用；阻止跨系统挂接 | 部门与映射测试通过 |
| 系统隔离 | 业务关系使用 `system_id` | 避免系统代码成为业务外键 | 仓储及 API 隔离测试通过 |
| 权限 | 使用关系化 RBAC 与部门范围 | 支持系统/部门作用域 | 安全测试通过 |
| 动态字段 | 使用带类型列的关系值行 | 消除运行时 JSON，支持约束和引用完整性 | 元数据与记录测试通过 |
| 主子模型 | 主记录、子记录和值分别建表 | 保留通用 MDM，移除 personnel 专用表 | 服务与控制器测试通过 |
| 审批 | 请求、变更、动作、审批人分表 | 防止伪造审批快照并保留审计 | 工作流测试通过 |
| 推送 | 订阅与投递日志关系化，服务端生成快照 | 提供幂等、并发安全和载荷限制 | 集成测试通过 |
| 初始化 | 仅显式开启本地 demo bootstrap | 防止非本地环境注入演示数据 | 初始化器测试通过 |
| 前端 | 元数据驱动通用列表、表单和管理器 | 一个工作台支持不同对象类型 | Vitest 与构建通过 |
| 遗留清理 | 删除 personnel、JSON 字段及其旧审批/推送路径 | 消除双轨运行和同表映射风险 | ArchitectureGuardTest 约束生产源码 |
