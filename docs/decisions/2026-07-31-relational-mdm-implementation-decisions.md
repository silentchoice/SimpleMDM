| 快照保密 | 日志列表按记录访问范围过滤并只返回摘要；完整请求/响应快照仅管理员详情接口返回 | 审计元数据和快照都可能暴露不可见记录，不能向普通查看者泄露 | DENY/缺失记录列表过滤测试、非管理员详情 403、管理员详情 200 通过 |

| 元数据治理 | 主字段、子类型和子字段仅允许有 `MDM_FIELD_MANAGE` 的当前系统用户创建、更新或停用；所有变更写 V4 审计 | 已使用字段的类型/唯一约束保持稳定，子字段 `shared` 决定跨部门投影 | 元数据控制器、服务、映射和迁移测试通过 |
| 编辑与分发解耦 | 主记录编辑仅依赖记录编辑能力；端点与订阅管理仅依赖字段管理能力；手动分发单独依赖 `INTEGRATION_MANUAL_PUSH` | 避免把出站能力隐式授予可编辑者，或因无出站能力阻断正常审批提交 | MDM 与集成控制器回归测试通过 |

| 前端 | 元数据驱动列表/表单，审批详情按主子差异分组，按钮使用服务端 capability | 一个工作台支持动态对象，同时避免前后端权限漂移 | Vitest 与 Vite production build 通过 |

## 关键语义

### 整单审批原子性

启用审批的创建或更新请求只形成草稿。草稿记录目标对象、部门、记录版本、主字段旧值/新值，以及每个子行的 `CREATE`/`UPDATE`/`DELETE` 和对应子字段差异。批准入口忽略客户端声称的审批人，以 JWT 当前用户为准；服务端锁定请求并再次检查审批分配、目标状态、主/子版本、元数据和唯一约束。全部生效数据、审批动作与自动分发事件使用同一事务提交，任何异常都整体回滚。

### 共享投影

`FULL` 用于管理员和授权范围内的本部门读取；`SHARED` 用于拥有跨部门查看能力但不在目标部门完整范围内的读取。当前主记录字段仍完整返回，重复子表只返回活动子记录中活动且 `shared=true` 的字段；审批详情在 `SHARED` 下采用相同子字段过滤。任何 `DENY` 目标按 404 处理。

### 分发与重试

批准产生的自动事件使用稳定事件标识，避免相同记录版本重复入队。手动分发创建新的逻辑事件；失败重试在同一日志行上 CAS 重新入队，保留原 `log id`、`event_id`、请求快照和初始触发字段，并写入最近一次人工重试审计。任务可重复投递同一逻辑事件，因此交付承诺是 at-least-once，而不是 exactly-once。完整快照只在管理员详情接口可见；普通日志列表不返回快照。

生产 Endpoint 策略不允许使用 localhost 作为 HTTP 验收接收端。最终本机验收先证明 API 拒绝 localhost，再使用直接写入的本地受限 fixture 仅验证权限、事务入队和策略层失败；生产策略未放宽，也没有向公网发送业务数据。
