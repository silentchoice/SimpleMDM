# 部门作用域元数据设计

**日期：** 2026-08-04

## 目标

主类型模板由超级管理员预先创建并分配给部门。部门编辑人员只能维护本部门的字段和子类型；即使多个部门使用同一个主类型模板，各部门的元数据结构也完全独立。任何部门结构变更必须经过本部门审批，审批通过前不得影响当前生效结构。

## 权限边界

- `SUPER_ADMIN`：创建、修改和停用主类型模板；将模板分配给部门；查看各部门配置。不能代替部门编辑人员提交部门结构变更。
- `DEPT_EDITOR`：为本部门已分配的主类型提交主字段、子类型和子字段结构变更。
- `DEPT_APPROVER`：审批或拒绝本部门的元数据结构变更。
- `DEPT_VIEWER`：只读取本部门已审批生效的字段结构。
- 所有写入和读取都在服务层校验当前用户状态、角色和部门，客户端传入的部门 ID 不能扩大访问范围。

## 数据模型

`master_types` 继续保存全局模板。`department_master_types` 保存部门与模板的绑定，并增加数据库唯一约束，保证每个部门最多绑定一个活动主类型模板；同一模板可以分配给多个部门。

部门结构表按部门隔离：

- `master_fields` 增加 `department_id`，唯一键调整为 `(department_id, master_type_id, code)`。
- `sub_types` 增加 `department_id`，唯一键调整为 `(department_id, master_type_id, code)`。
- `sub_fields` 增加 `department_id`，唯一键调整为 `(department_id, sub_type_id, code)`。

新增 Flyway 迁移完成列、外键和唯一约束调整。现有数据若没有明确部门归属，迁移必须失败并给出可诊断信息，不得猜测归属。

字段定义状态至少包含 `PENDING`、`ACTIVE` 和 `DISABLED`。业务结构查询只返回 `ACTIVE` 数据。

## 变更与审批流程

部门编辑人员提交结构变更时：

1. 服务端从当前登录用户确定 `department_id`。
2. 校验该部门已分配目标主类型，且目标子类型也属于该部门。
3. 校验字段编码、字段类型、选项结构和唯一性。
4. 读取当前生效结构形成不可变 `before_snapshot`。
5. 根据请求形成不可变 `after_snapshot`。
6. 创建归属于该部门的 `approval_tasks` 记录；不修改任何 `ACTIVE` 定义。

本部门审批人员通过时，在单一数据库事务内锁定审批任务，重新校验任务状态，然后应用 `after_snapshot`、更新结构版本并标记任务通过。拒绝时只更新任务状态和原因，当前结构保持不变。重复审批返回 409。

审批任务使用明确的元数据实体类型，例如 `MASTER_FIELD_SCHEMA`、`SUB_TYPE_SCHEMA` 和 `SUB_FIELD_SCHEMA`。`entity_id` 指向相应的部门作用域结构或稳定的聚合标识。

## 字段结构校验

支持 `TEXT`、`NUMBER`、`DATE`、`DATETIME`、`SELECT`、`RADIO`、`MULTISELECT` 和 `SWITCH`。

- 字段编码必须符合 `[A-Za-z][A-Za-z0-9_]{0,63}`，同一部门作用域内唯一。
- `SELECT`、`RADIO`、`MULTISELECT` 必须提供非空、去重且不含空白值的选项。
- 其他字段类型不得携带选项。
- 必填字段拒绝缺失、空白文本和空集合。
- 动态数据拒绝未知字段、错误类型、非法日期时间及范围外选项。
- 子字段的 `share_config` 只控制跨部门读取，不能改变字段归属或写权限。

## API

保留设计约定的接口族：

- `/api/master-type`：超级管理员维护模板及部门分配。
- `/api/master-field`：查询已生效字段；部门编辑人员提交字段结构变更。
- `/api/sub-type`：查询已生效子类型；部门编辑人员提交子类型结构变更。
- `/api/sub-field`：查询已生效子字段；部门编辑人员提交子字段结构变更。
- `/api/approval`：本部门审批人员查询和处理元数据审批任务。

兼容接口不得绕过相同的服务层授权和审批逻辑。成功响应继续使用 `{ code, message, data, requestId }`。参数错误返回 400，未认证返回 401，跨部门或角色不符返回 403，不存在返回 404，重复编码、重复分配和状态冲突返回 409。

## 测试与验收

- 单元测试覆盖字段值校验、字段结构校验、角色权限和部门边界。
- 控制器测试覆盖约定接口路径、统一响应和错误状态。
- 仓储集成测试覆盖部门单模板唯一约束、部门字段唯一约束、JSON 选项往返和审批事务。
- 审批测试证明提交后生效结构不变、通过后原子生效、拒绝后保持不变、跨部门审批被拒绝。
- 两个使用同一模板的部门分别修改字段后，查询结果互不影响。

Docker/Testcontainers 验收按用户当前指示暂时跳过；其余非容器测试必须通过。真实 MySQL 迁移与事务测试保留为部署前必做验收项。
