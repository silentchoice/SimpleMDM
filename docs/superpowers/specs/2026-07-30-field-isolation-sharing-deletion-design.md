# 主子表字段隔离、共享与删除设计

## 目标

本次改造解决动态主表与子表字段标识混用、子表共享规则分散、字段无法删除，以及演示数据字段含义重叠的问题。

完成后：

- 同一系统内，主表和所有部门子表的 `field_key` 全局唯一。
- “是否共享”只属于子表字段定义。
- 删除记录级可见性配置，以字段定义的共享状态作为唯一跨部门可见性规则。
- 主表字段不可删除。
- 本部门管理员可以删除本部门非系统子表字段，并同步永久清理历史 JSON 数据。
- 主管理员不能删除字段。
- 演示主表和各部门子表使用完全不同的字段标识。
- 重置现有业务演示数据并生成一批新的演示数据。

## 字段模型与数据库约束

`mdm_field_definition` 增加 `shared` 非空布尔字段，默认值为 `false`。

- `table_type=master` 时，`shared` 固定为 `false`，接口忽略或拒绝其他值。
- `table_type=sub` 时，部门管理员可以配置 `shared`。
- 字段响应始终返回 `shared`，便于前端统一处理。

增加唯一约束：

```text
(system_code, field_key)
```

该约束保证同一系统内：

- 主表字段不能与任何子表字段重名。
- 不同部门的子表字段也不能重名。
- 不同系统之间仍可使用相同 `field_key`。

创建字段时，服务层先查询冲突字段并返回包含来源的友好错误；数据库唯一约束负责防止并发请求绕过校验。

## 子表共享规则

删除现有记录级 `visibility` 编辑能力。跨部门可见性只由字段定义的 `shared` 决定：

- 查看本部门子表时，返回该部门全部字段和值。
- 查看其他部门子表时，只返回 `shared=true` 的字段和值。
- 非共享字段既不返回字段定义，也不返回对应值。
- 主表字段不参与共享配置，继续按系统全局共享。

已有 `visibility` 物理列可暂时保留以降低数据库迁移风险，但业务接口、界面和权限判断不再读取或写入该列。后续可在独立迁移中删除。

## 删除规则与权限

`DELETE /api/dept-fields/{id}` 的规则为：

1. 字段不存在：返回 404。
2. 主表字段：拒绝删除。
3. 系统字段：拒绝删除。
4. 主管理员：拒绝删除，不因 `isAdmin=true` 获得绕过权限。
5. 字段不属于当前用户部门：拒绝删除。
6. 当前用户没有本部门 `EDIT` 权限：拒绝删除。
7. 满足以上条件时，删除本部门非系统子表字段。

删除在单一事务中完成：

1. 查询该部门、该子表字段组下的全部子表记录。
2. 解析每条记录的 `data_json`。
3. 永久移除被删除的 `field_key`。
4. 保存清理后的记录。
5. 删除字段定义。

任何 JSON 无法解析或数据库写入失败时，整个事务回滚；不能出现字段定义已删除但历史数据未清理的部分成功状态。

## 后端结构

新增字段定义服务，承载以下业务规则：

- 创建字段时的全系统标识唯一校验。
- `shared` 的主子表约束。
- 删除权限校验。
- 删除字段与历史 JSON 清理事务。
- 根据查看者部门过滤子表共享字段和值。

控制器只负责请求解析与响应，不直接实现事务和数据清理。

仓储层增加：

- 按 `systemCode + fieldKey` 查询冲突字段。
- 按部门和子表字段组查询需要清理的子表记录。
- 支持共享字段查询或由服务层对已查询定义进行明确过滤。

## 前端交互

字段管理页：

- 保留“主表字段（共享）”和“子表字段（部门隔离）”页签。
- 仅子表字段表格和编辑弹窗展示“是否共享”。
- 主表字段不展示删除按钮。
- 当前用户为部门管理员、拥有本部门 `EDIT` 权限且不是主管理员时，子表字段展示删除按钮。
- 删除前显示不可撤销确认：

  > 删除后，该字段定义以及所有历史子表记录中的对应数据都会永久清除。

- 删除成功后重新加载字段列表。

人员详情页：

- 移除子表记录的“可见性”列和编辑控件。
- 本部门查看显示全部本部门字段。
- 跨部门查看只显示后端返回的共享字段。

## 演示数据重置

保留用户账号、部门权限和审批人配置，清理并重建：

- 人员主数据。
- 人员子表数据。
- 字段定义。
- 审批记录。
- 与这些演示记录直接关联的推送日志。

新的演示字段必须满足同一系统内 `field_key` 完全不重复。例如：

- 主表：`employee_code`、`employee_name`、`gender`、`job_title`、`mobile_phone`、`work_email`。
- 工程部项目子表：`engineering_project_name`、`engineering_project_role`、`engineering_allocation_rate`。
- 工程部薪酬子表：`engineering_base_pay`、`engineering_performance_bonus`。
- 人力资源部合同子表：`hr_contract_type`、`hr_contract_term`、`hr_contract_expiry_date`。
- 产品部目标子表：`product_quarter_target`、`product_delivery_rate`。

种子初始化前需要显式清理目标业务表，随后按外键依赖顺序重建演示数据。初始化过程应可重复执行，并验证不存在重复字段标识。

## 错误处理

- 字段标识冲突：返回 400，并指出已存在字段所属的主表或部门子表。
- 主表字段删除：返回 403，“主表字段不可删除”。
- 系统字段删除：返回 403，“系统字段不可删除”。
- 主管理员删除：返回 403，“主管理员无字段删除权限”。
- 跨部门删除：返回 403，“只能删除本部门子表字段”。
- 缺少本部门编辑权限：返回 403，“无本部门字段删除权限”。
- 历史 JSON 清理失败：返回 500，事务回滚并保留全部原数据。

## 测试策略

后端测试覆盖：

- 主表与子表字段标识冲突。
- 不同部门子表字段标识冲突。
- 不同系统允许相同字段标识。
- 主表 `shared` 固定为 `false`。
- 本部门查看全部子表字段，跨部门只查看共享字段。
- 主表、系统字段、主管理员、跨部门和无权限用户的删除拒绝。
- 合法删除同时移除字段定义和全部相关历史 JSON 值。
- JSON 解析或保存失败时事务回滚。
- 新演示字段在系统内没有重复标识。

前端测试覆盖：

- 共享开关只在子表页签出现。
- 主表字段不显示删除按钮。
- 合法部门管理员看到子表删除按钮。
- 主管理员和无权限用户看不到删除按钮。
- 删除确认文本明确说明历史数据永久清除。
- 删除成功后刷新字段列表。
- 人员详情不再显示或提交记录级 `visibility`。

## 验收标准

- 无法在同一系统内创建重复 `field_key`，无论字段属于主表、哪个子表或哪个部门。
- 子表字段共享状态可新增、编辑并正确控制跨部门显示。
- 页面和接口均不再使用记录级可见性。
- 主表字段始终不可删除。
- 只有本部门管理员能够删除本部门非系统子表字段。
- 删除后数据库字段定义和相关历史 JSON 值均消失。
- 主管理员不能删除字段。
- 重建后的演示字段全部不同，人员主数据、子表数据和审批数据能够正常展示和操作。
